5. Architectural Scope & API 670-Style Latching
Advisory Edge Diagnostic Architecture
AC Engine operates strictly as an embedded advisory condition-monitoring engine. It ingests 32-sample tri-axial integer counts directly from the sensor FIFO and outputs deterministic telemetry:
typedef struct {
  ac_condition_t condition;    // NORMAL, INCIPIENT, CRITICAL, SENSOR_ERR
  uint8_t        health_index; // 0% (Failure) to 100% (Pristine)
  uint16_t       harmonic_q8;  // Q8 Parseval vibration energy
  uint16_t       crest_q8;     // Q8 fixed-point 3D Crest Factor
  bool           trip_latched; // API 670-style software latch
} ac_result_t;
Host MCU firmware reads this struct and controls Modbus/CAN telemetry or triggers safety relays.
API 670-Style Software Latching Logic
  • 2-Window Confirmation Gate (≥128 ms): Impact spikes must persist across ≥ 2 consecutive windows before asserting critical trip.
  • Persistent Software Trip Latch: Once latched, `trip_latched` holds across sensor dropouts, motor spin-downs, and baseline resets.
  • Explicit Operator Reset: Clears only via `ac_engine_reset_trip()`.
Qualification Boundary: AC Engine provides software advisory trip logic; certified emergency shutdown contactors remain the responsibility of host safety relays.
