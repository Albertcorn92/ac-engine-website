5. Architectural Alignment & Safety Standard Scope
Advisory Edge Diagnostic Architecture

AC Engine operates strictly as an embedded advisory condition-monitoring engine. It ingests 32-sample tri-axial integer counts directly from the sensor FIFO and outputs continuous machine health telemetry:

typedef struct {
  ac_condition_t condition;    // NORMAL, INCIPIENT, CRITICAL, SENSOR_ERR
  uint8_t        health_index; // 0% (Failure) to 100% (Pristine)
  uint16_t       harmonic_q8;  // Q8 fixed-point Parseval vibration energy
  uint16_t       crest_q8;     // Q8 fixed-point 3D Crest Factor
  bool           trip_latched; // API 670-style persistent software latch
} ac_result_t;

The host MCU application firmware reads this struct and decides whether to log telemetry, alert an operator via Modbus/CAN, or trigger an emergency shutdown contactor.

API 670-Style Software Latching Logic

To prevent false shutdowns, AC Engine implements software trip interlock logic aligned with API 670 machinery protection principles:

  • 2-Window Confirmation Gate (≥128 ms): Mechanical impact spikes must persist across at least 2 consecutive windows to latch a critical shutdown state.
  • Persistent Software Trip Latch: Once latched, `trip_latched` remains asserted across sensor dropouts, motor spin-downs, and baseline resets.
  • Explicit Operator Reset: Clears only via `ac_engine_reset_trip()`.
Qualification Boundary: AC Engine provides software-level advisory trip logic; certified physical emergency shutdown contactors remain the responsibility of host safety relays.
